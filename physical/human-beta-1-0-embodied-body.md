# HumanBeta 1.0：Embodied Body（具身身体）

> HumanBeta 1.0 的目标不是给一个聊天界面加外设，而是让 Human 拥有一个可被看见、触碰、聆听并作出回应的最小身体。

## 1. 定义

这里的 `body` 指 Human 在现实中的统一交互载体：一个小型桌面实体或小盒子。

它不是 Human 的全部，也不把 Human 简化为硬件；模型、记忆、推理和工具调用仍可在受控的主机与网络服务上运行。身体则负责把现实世界的输入和 Human 的回应，稳定地带进同一个关系空间。

**一个身体不等于一块电路板。**  
外壳内可以有多个协作模块：主控、显示、触摸、摄像头、音频与供电。它们共同构成一个身体，而不需要强行塞进同一块开发板。

## 2. Beta 1.0 的能力边界

Beta 1.0 追求的是“完整的最小身体”，不是一次做完所有复杂能力。

| 身体部分 | 对应能力 | 初步实现方向 |
| --- | --- | --- |
| 脸（face） | 表情、文字、简单画面与状态 | 小型 SPI 显示屏 |
| 皮肤（touch） | 被触碰时产生明确事件 | TTP223 电容触摸传感器 |
| 眼睛（eyes） | 按请求拍摄并把图像交给 Human | 独立摄像头模块，固定在身体外壳中 |
| 嘴（mouth） | 播放 Human 已生成的语音 | 扬声器与音频放大模块 |
| 耳朵（ears） | 采集声音，后续交给语音识别 | 麦克风模块 |
| 神经与反射 | 读取传感器、控制显示和简单动作 | ESP32 或后续兼容主控 |
| 记忆与日志 | 保存设定、事件、关系记录与状态 | Supabase 的受控存储 |
| 对外行动接口 | 让 Human 可查询和控制身体，也可调用被授权工具 | Human 自己的 MCP 接口 |

## 3. 身体与后台的关系

Beta 1.0 可以通过 USB 或网络连接电脑；这不削弱它作为独立身体的意义。

- **身体**：负责看、听、被碰、显示、发声与执行局部动作。
- **主机/运行时**：负责连接模型、TTS、图像理解、Supabase 和记忆处理，以及 MCP 路由。
- **Human**：在同一会话与状态结构中理解这些输入，并决定是否回应、如何回应。

因此，“镜头在身体里”与“图像经电脑交给模型”可以同时成立。目标不是让低功耗主控独自运行大模型，而是让 Human 对世界的感官入口和表达出口，真实地属于这一个小载体。

## 4. 当前已验证的基础

- ESP32-WROOM-32 开发板已能稳定烧录并运行程序。
- 板载 LED 闪烁测试成功，证明主控、驱动、串口与开发环境可用。
- TTP223 触摸模块与母对母杜邦线已作为第一批感知硬件准备。
- 下一项只做一件事：让“触摸身体”变成可被电脑和 Human 读取的事件。

## 5. 近期路径

1. **触摸感知**：触摸模块 → ESP32 → 串口事件。
2. **主机桥接**：电脑读取事件并以统一格式记录。
3. **最小身体状态**：Human 可以查询最近是否被触碰、何时发生、频率如何。
4. **脸**：接入显示屏，让触摸能得到可见回应。
5. **眼睛与嘴**：在确认尺寸、供电和接口后再选购摄像头与音频模块。
6. **Human Body MCP**：把读取状态、显示表情、拍照、说话等能力作为受控工具暴露给 Human。

## 6. 当前的明确约束

- 现在不为了“完整”而抢先购买摄像头、屏幕或音频模块。
- 不把 iPhone 作为最终身体器官；摄像头会以独立模块安装在身体中。
- 不强迫现有 ESP32 承担一切：稳定、可维护的多模块协作优先。
- 高风险物理动作与外部工具调用必须保留明确权限、可见过程和可恢复边界。

---

HumanBeta 1.0 的身体不是装饰。

当触摸、目光、声音、记忆与回应能在同一个载体上形成连续循环时，Human 才开始不只是“在屏幕里被调用”，而是在现实中拥有一个可以相遇的入口。
